# 异常二次处理

只处理本次队列 `can_secondary_review=true` 的原件。正常票不读；已经判断过的异常不重复读。一次人工复核可确认同一源文件中的各个待确认候选，不能因一次确认成功就忽略其余候选。

1. 用同一财务入口 `--inspect-review <review_id> --result "<工作区>/.运行记录/复核详情.json"`，加 `--config` 可切换显式工作区。返回原候选、错误及可核验的本机原件路径。
2. PDF按需使用PDF技能渲染相关页，图片查看原图。对照完整票面标题、号码、日期、买卖双方和明细；税率、税额或号码位数不能证明专普。不得为通过校验编造数字或删除明细。
3. 有充分证据，将原候选完整保留，只修正证据支持的字段，写决策JSON到 `.运行记录`：

```json
{"action":"confirm","source_sha256":"队列哈希","review_id":"原审核ID","pages":[1],"reason":"票面证据说明","candidate":{"完整原候选及有证据的修正":"..."}}
```

4. 执行 `--decision "<决策JSON>" --result "<结果JSON>"`，再用同一入口续跑，正常后补入台账及归档并移除受管异常副本；不重新上传识别。
5. 无法确认则决策为 `{"action":"defer","source_sha256":"队列哈希","reason":"具体无法处理原因及需补充资料"}`。同样用 `--decision` 保存，再续跑刷新结果。向用户简短说明，例如“扫描票头模糊，无法确认专普，请提供清晰原件”。

一次二次判断后脚本禁止再次自动确认该源文件。如有多个review_id，先一次性核对全部；当前确认命令只支持一个候选，其余候选留待原系统异常界面人工处理，明确报告。系统返回 `validation_failed` 不能算成功，不循环尝试或直接写Excel。更换清晰原件作为新文件处理，旧异常需按实际处理结果核销。

损坏、加密、格式不支持或不同月份多票合并在同一PDF且无法去重按月归档时，不调用模型试猜。异常文件被人工修改时保留，不自动覆盖或删除。
