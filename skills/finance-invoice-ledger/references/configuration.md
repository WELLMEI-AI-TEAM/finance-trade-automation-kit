# Configuration

## Desktop finance workspace (default)

The local `binding.local.json` selects the workspace; its config is `<workspace>/.运行记录/财务配置.json`. A clean installation asks for the parent directory and uses `setup_workspace.py` to create `台账处理`; see [workspace-setup.md](workspace-setup.md). Do not bundle another machine's binding or credentials. Python requires `httpx`, `openpyxl`, and `PyMuPDF` (`fitz`). Without `--input`, scan `待处理` recursively and PDF/images directly in the root. Explicit `--input` accepts attachment paths; existing pending batches still resume.

Required: `base_url`, `username`, `credentials_file` (or `password_env`), `workspace_root`. Optional: `input_dir`, `archive_dir`, `ledger_dir`, `exception_dir`, `backup_dir`, `state_path`; every output must remain inside the root and business directories cannot overlap. If `ledger_path` is given it must be an xlsx directly inside `ledger_dir`; otherwise adopt the unique existing xlsx or create `财务发票台账.xlsx`. Multiple candidates require explicit selection. Template header compatibility is checked by the existing backend before replacing anything; incompatible books are retained.

`archive_month_layout` is `year.month` for newly initialized workspaces (`发票/2026.10`); existing configs without it retain `year/month` (`发票/2026/10`). Deduplication covers the entire configured archive tree across both layouts and all months. Existing byte-identical originals are reused in place, with `archive_location_warnings` for a wrong-month location. See [archive-dedup.md](archive-dedup.md) for historical different-byte identity verification limits; a recursive hash scan is not proof of complete business deduplication.

State and queue live in `.运行记录`; keep these files. Byte and invoice-ID deduplication, source mapping, backup index, review decisions and crash recovery depend on them. The normal CLI entry automatically removes this invocation's unchanged inputs only from the configured inbox, after workflow state, queue and initial result are durable. Completed normal inputs require full source identity coverage in both exported ledger receipts and verified archives; exception inputs require a verified exception copy, matching reason and queue entry. Existing duplicates are cleaned without another recognition or export. Failed/incomplete/changed inputs stay in place with an error. Do not recursively empty the inbox, remove new arrivals or follow junctions/symlinks. Root-level files and external attachments remain at their original locations. `cleaned_input_files` and `retained_input_files` report cleanup; retry after a cleanup failure uses existing processing records. Only completed normal sources enter the archive. An exception in one source does not block other normal sources in the batch; any unresolved review inside one PDF holds back that entire PDF. Exact bytes spanning different invoice months require split originals to satisfy both monthly placement and content deduplication. Secondary review uses [secondary-review.md](secondary-review.md).

Business folders contain only their intended financial files. `.运行记录` is hidden on Windows and holds fixed result JSON, review evidence, decisions and required diagnostics. Do not generate unsolicited reports, instructions or helper scripts in the workspace. New workspace locks live under the local application data `InvoiceLedgerSkill/locks`, keyed by canonical resource path, so separate workspaces/installations still share protection for a common resource. Existing sidecar guards remain hidden and are also acquired for compatibility; never delete them as cosmetic cleanup. Qwen result and decision paths must be within `.运行记录`.

Exception originals and their reason notes are grouped in `异常未处理发票/YYYY-MM-DD_HH-MM-SS` using this invocation's Beijing time. Independent invocations in the same second receive a numeric suffix. A source's saved exception path stays stable across retries; resolved copies and empty managed time folders are removed. Existing flat managed exceptions are relocated with a persisted copy-before-delete plan and updated state/queue pointers, without recognition or ledger export. Modified files stop relocation and remain intact.

The backend must support explicit invoice-ID export selection, template normalization and the opt-in batch source manifest. Response capability checks stop publication against an older backend. Do not import each workbook into global ledger history. Retain historical duplicates, values, formulas and comment text; repeated identity checks and formatting use the service. Each actual ledger write (including initial creation) prepares `备份/YYYY-MM-DD_HH-MM-SS/` in Beijing time with exactly two subfolders: `本次处理的发票/` for the current invocation's input snapshots (including invalid inputs, deduplicated by source hash) and `旧台账/` for the previous workbook bytes, empty on initial creation. Unchanged output creates no backup. Retain the latest 10 managed groups and rotate whole groups. Metadata stays in the hidden state. Legacy flat backups migrate without recognition; their invoice subfolder stays empty when historical input association is unavailable. If an old managed backup or exception was edited by a person, or a backup contains extra user files, preserve it and report the conflict. Backed-up invalid inputs never become accepted invoice archives.

## Legacy explicit profiles

The remainder describes old configs without `workspace_root`, including `profiles/local-test.json`. These still use the original workflow and flat archive directory. Their behaviors do not override the desktop rules above.

Use a separate configuration/state file for each account, archive directory and ledger. The backend must be reachable and use real extraction, not offline fixtures. Python requires httpx and openpyxl.

Required fields: `base_url` (service root without /api/v1), `username`, `input_dir`, `archive_dir` (long-term local copies), `ledger_path` (absolute .xlsx filename), `state_path` (absolute JSON file). Credentials come from either `credentials_file` (one line: username password) or environment variable named by `password_env` (default INVOICE_SKILL_PASSWORD). Optional `wait_seconds` defaults to 900 and `poll_seconds` to 3.

Use the user's chosen production paths. During tests use independent output directories. Never point the long-term archive at the backend's retention-managed archive directory. Do not import the fixed workbook into global backend history on each run.

On timeout or save failure, rerun the same configuration. Inspect errors before altering state. Do not delete state to force a rerun; doing so removes recognition reuse. Kernel locks release automatically after a killed process; persistent `.guard` files are harmless and must not be removed while workflows run. Legacy PID locks migrate only after the owner is confirmed dead; unknown or active owners remain protected. Submitted batches resume even if their original source files were moved; draft uploads still require unchanged source bytes. Completed manual-review history is allowed; unresolved reviews block publication.

Requires the backend's `unique_invoices=true` export contract, invoice manifest and validated-source archive restoration endpoints. The adapter fails closed against an older backend. New distinct files are submitted together (up to 500 per batch); the backend's configured document concurrency controls extraction. One completed batch is exported once. Existing saved single-file states are migrated automatically without recognition.

Preserve `.invoice-archive-index.json` in the archive directory alongside the workflow state file. The index is account-scoped and shared by multiple ledger configurations using that directory; it contains backend invoice IDs and verified local hashes. Unknown historical files are reported. Identical content can be adopted by hash; different unindexed historical files block new archive publication until identities have been reconciled. Use a fresh directory for initial testing rather than deleting historical documents.

Missing permanent files can be recovered from unchanged local source bytes only when their hash equals the backend archive hash, or from the backend's validated-source restoration endpoint. Neither path reruns recognition. A modified permanent file is treated as a conflict and retained. Ambiguous historical invoice numbers, financial conflicts or incomplete line items block automatic ledger append; fix the evidence rather than deleting old records. Historical duplicate reports are candidates, since legitimate identical line items can also have equal financial values.
