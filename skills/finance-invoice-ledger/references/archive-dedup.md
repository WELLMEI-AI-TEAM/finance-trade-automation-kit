# 指定发票目录内的查重与历史建档

查重范围是配置的 `archive_dir` 整棵树，默认 `<工作区>/发票`，涵盖全部月份，不扫描其他工作区或整台电脑。目录外文件和链接目标不作为已有归档依据。

先按 SHA256 筛选相同内容，再复用系统已核验的身份及关键字段判断不同字节的同票。税号是企业标识，文件名、短号、图片相似度仅能找候选。系统身份包括适用票种、代码和完整号码；红字票使用自身号码，不能与所引用蓝票合并。未支持票种保持未核验，不强套规则。

## 正常处理与费用控制

正常识别一次时，随已有 manifest 接口取得身份元数据，保存到 `.运行记录/归档身份索引.json`。判重不单独调用模型，不由会话逐票重读正常票。相同身份且关键字段、整份原件包含的发票集合均一致时，复用已有原件并登记来源别名；关键字段冲突或集合部分重叠则暂缓该来源，不覆盖旧件、不新增正常副本，也不先增加本次台账记录。

索引缓存未变化文件的哈希；Windows 使用文件 ChangeTime 检测变更，无法取得可靠变更时间时重新计算本地哈希；实际复用或发布前再次核验内容。整个归档树共用运行锁，发布不覆盖既有原件。移动文件按内容重连，缺失原件可恢复，被修改的原件需核对。跨月份找到已有原件时复用，位置不符仅报告，不自动移动。已有重复归档保留并报告，不自动清理。

台账和归档分别去重：原件已有但台账缺失允许补账；台账已有但原件缺失允许补归档。已知来源有持久化系统批次记录时直接复用，不重新上传识别。完成批次重复运行不重新识别、不重新导表、不新增归档。摘要只返回计数及少量异常样本；需要细查才读取结果文件中的相关条目，不加载完整状态进会话。

## 接管历史归档

入口优先通过旧运行记录和已保存的系统结果恢复索引，不重新识别。仍有未知或被修改历史原件时，未知新来源会暂缓，不能宣称已完成全量业务查重；正常运行不会自动启动大规模历史识别。

用户要求接管历史归档或补齐历史索引时，单独执行一次限量建档：

```powershell
# Codex 安装：
python "<本Skill目录>/scripts/run_finance.py" --index-history --history-limit 20
# 千问办公安装：
python "<本Skill目录>/scripts/run_qwen.py" --index-history --history-limit 20
```

自定义配置/隔离工作区沿用正常入口的配置参数。建档不能与 `--input` 同时使用。数量范围1到500，默认20；大历史库分次执行，按返回的未完成数继续，不在一次会话里无上限循环。首次未关联历史文件才通过现有系统识别，保留批次以恢复；已核验文件和同字节副本不重复识别。超时后本轮停止等待，下次命令复用原批次。不要删除索引、批次或原件来重试。

建档不导出台账、不下载归档、不移动或删除历史原件。完整结果默认 `.运行记录/历史建档结果.json`；`status=partial` 或退出2表示尚有未核验项/错误，并非全量完成。`unresolved_history` 给出路径和原因，`history_reviews` 给出系统待审核项。损坏、加密、不支持、系统审核未完成或原件集合冲突时保持待确认；需系统复核的先在系统处理后续跑，不凭文件名补身份。

未核验数归零后，原命令续跑会解除历史索引导致的暂缓；台账历史重复仍只报告。若长期存在无法核验历史，报告具体阻断原因，等待使用人员核对或明确调整管理范围，不为追求完成率擅自排除旧票。

同一 PDF 可能含多张票，只有完整集合相同才可复用。任一未解决异常使整份源文件暂缓；跨月份原件沿用系统规则，不自行拆改票面。
