# 批次接收、分类与原件备份

## 输入与工作根目录

“处理这些文件”等明确处理请求即可调用本 skill，无须每次输入 skill 名。接收当前对话附件、明确文件路径、目录或其中压缩包；不启动文件监控。

1. 用户明确给出结果/工作根目录时优先采用。否则：指定路径末级为“待处理”时以父目录为工作根目录；指定目录包含“待处理”时以该指定目录为根并只读取其“待处理”；其他指定目录本身作为根并扫描其中输入。用户明确要求重新处理“待核对”时，以其所属工作根目录为根，只将指定的待核对文件列入本次 inputs。
2. 仅附件或散列文件路径、没有可推断的工作根目录时，默认使用本机系统桌面下“出关合同”。Windows 用 `[Environment]::GetFolderPath('Desktop')` 获取系统桌面，不硬编码账号或假定桌面一定在用户主目录。
3. 只处理本次附件/指定的文件集合。不把以前的附件、处理结果、备份或待核对文件自动加入本批。扫描根目录时排除“处理结果”“备份”“待核对”整棵目录；仅用户明确要求时重试指定待核对文件。
4. 明确给定空目录就说明无待处理文件，不改为自动扫描其他位置。存在多个工作根目录且无法从请求确定结果位置时，完成来源盘点后仅询问结果根目录。

## 先备份，再处理

写一个位于任务临时区的 UTF-8 请求 JSON，用下面脚本创建本批目录并完成原件备份。脚本仅使用 Python 标准库；它不进行正文分类、业务匹配或合同生成。

```json
{
  "root": "C:/Users/实际账号/Desktop/出关合同",
  "inputs": ["C:/Users/实际账号/Desktop/出关合同/待处理"]
}
```

`inputs` 可列多个附件本地路径、文件或目录。采用根目录的“待处理”时可以省略；显式空列表无效。附件仍在会话存储时先取得实际可读文件；无法访问则说明缺项，不伪造来源。输入没有文件时不建立空批次。

```powershell
& '<可用Python绝对路径>' '<skill绝对路径>\scripts\prepare_batch.py' --request '<请求JSON绝对路径>'
```

脚本返回 `batch`、`result_dir`、`backup_dir`、`pending_dir` 和逐文件 `source → backup` 映射，生成北京时间 `YYYY-MM-DD_HHMMSS`；同秒重跑使用 `_02` 等后缀，备份、结果与待核对共用一个编号。`backup_status=verified` 才能继续。备份未完成时停止该批；保留已有部分副本及失败记录，不发布合同，也不把部分备份报告为成功。

全量备份包括本批全部输入原文件、原始压缩包、无法识别/未匹配/待核文件，不仅是成功生成合同所用的文件。保留各输入的相对层级，用输入序号隔离同名附件。工作文档从备份复制到临时工作区使用，保持备份本身不变；Excel/WPS也只打开隔离副本。原输入不移动、不覆盖、不自动清空；不按次数删除备份。

压缩包本体先原样备份，再从备份解压到临时工作区，拒绝绝对路径、路径穿越、链接和越界成员。压缩包内可识别的PI/购货合同/订单确认书归入相应结果位置，并记录 `原压缩包路径::成员路径`；不要把解压产生的文件误记为用户直接提供的原文件。

## 固定结果结构

```text
出关合同/                         工作根目录，名称可以由用户指定
  待处理/                         常用输入目录
  处理结果/
    2026-10-28_143025/
      出口合同/                   仅通过核验的最终合同，命名如WMDS26308 ER26007.xlsx
      PI/                         本批PI原样副本
      购货合同/                   本批购货合同原样副本
      订单确认书原文件名.xlsx       完整原表，直接在批次根层
      核验报告.md
      批次记录.json
  备份/
    2026-10-28_143025/
      原文件/                     本批所有原文件，包含原ZIP及未识别文件
      备份清单.json
  待核对/
    2026-10-28_143025/             仅本批存在未能处理文件时创建
      未能处理的原文件             原样副本，保留源文件
      待核对说明.md                文件名、原因和缺失/冲突信息
```

按正文识别类别；PI、购货合同即使尚未匹配或日期待核，也保留原样分类副本并在报告中注明。多个订单确认书完整复制至批次根层，不拆表、不汇总重制、不删行；同名文件采用稳定后缀且禁止覆盖。分类副本逐一比较备份SHA256；合同副本按原有业务和保真规则核验。

仅最终出口合同统一命名为 `购货合同编号 我方订单号.原扩展名`，依据见SKILL.md的交付规则；保留拆单后缀，不加“_出口合同”。原PI、购货合同、订单确认书和备份副本保留原文件名，分类副本重名时保留来源层级或加稳定后缀。成品命名缺项、关联不唯一或同名不同内容的文件进入待核对，不套用分类副本的后缀规则。

临时解压文件、计划、引擎草稿、审计JSON、渲染图放任务工作区，或批次目录下明确的“核验资料”目录，不能混入最终“出口合同”。失败或未完成的草稿保留为待核材料，并明确标注为草稿。

未能处理、匹配冲突、缺少关联资料、日期无法确定、读取/保真/视觉核验失败及无法识别的文件，必须将原样副本放入 `pending_dir`（即根目录“待核对/同一批次”），不能只在报告中列名。复制自已核验备份并核对SHA256；同名文件保留来源层级或加稳定后缀，禁止覆盖。压缩包内成员失败时保留该成员原样副本并关联原ZIP的备份位置；整包无法读取时将原ZIP原样放入待核对。需要人工核对一组关联关系时一并提供必要的原PI/购货合同/订单确认书副本；成功文件不因此改列失败。

在 `待核对说明.md` 记录各文件、原路径/ZIP成员、原件哈希、未能处理原因、需补充的信息及对应结果报告路径；批次记录中增加待核对副本路径和状态。默认不自动重试、移动或清空这些文件。

## 收尾

在 `核验报告.md` 记录输入与分类位置、关联证据、标题/日期改动、保真/视觉核验结果、成功数量、待核及无法识别的文件；保留现有业务规则，不因新目录流程放宽核验要求。

补充 `批次记录.json`：每个原件的类别/备份/分类副本，每份最终合同的路径与SHA256、其来源、处理状态和报告路径。已识别原件有副本且所有输入均有备份记录；未处理项写明原因。重新核对分类副本和备份哈希、输出文件数。用户要求处理的全部文件均需有结论，不能只报告成功组。

回复提供本批结果、备份及核验报告的路径，并说明成功/待核数量。仅创建了批次目录或备份不等于生成合同完成。
